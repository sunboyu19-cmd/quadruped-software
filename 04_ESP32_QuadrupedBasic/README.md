# 四轮足基本运动：两块普通ESP32＋4轮电机＋4总线舵机


目标主控是物料清单的 **ESP32-DevKitC V4 / ESP32-WROOM-32E / 4MB**，使用Micro-USB数据线，不是此前遥操手ESP32-S3。

- **A板 FRONT_MASTER**：左前轮1、右前轮2，连接唯一一块微雪Bus Servo Adapter(A)，控制全部四个STS3032舵机。
- **B板 REAR_FOLLOWER**：左后轮3、右后轮4；与A板用UART通信。
- 编号按用户实物：**1左前、2右前、3左后、4右后**，轮电机与腿舵机采用相同位置编号。
- 动力为电池→6V稳压器→轮驱动/舵机。母线参数6.0V，7极对，校准1.5V，运行电压限幅2.5V。
- 提供前进、后退、原地转向、单轮测试、单关节点动、四关节姿态小范围调整。先按实物完成方向和中位标定，再做整车运动；这是手动基础控制程序，尚需整机实物验证。

四个MiniFOC仍使用3PWM、高电平EN接口；AS5600每个地址均为0x36。每块ESP32的两路I²C各放一个编码器。四个舵机ID必须分别为1、2、3、4，整条舵机总线只由A板发送指令，不能把两块ESP32的TX同时接微雪板。

## 当前版本与入口

### 运动速度与转弯更新

目前行驶速度指令上限12 rad/s，默认2；原地旋转分量上限4 rad/s，默认2，按住按钮或A/D持续旋转、松开停轮。弧线与原地旋转独立：弧线差速=min(4,行驶速度×弯道强度)，强度0.1～1，默认0.7；每侧超12时等比例缩放。默认前进分量2、弯道强度0.7时左右约0.6与3.4 rad/s，转向更明显。

电机运行电压限幅按用户要求保持2.5V；母线仍6V，校准电压仍1.5V。速度指令上限仍为12 rad/s，但不保证负载下能达到。当前没有实测电流闭环、温度检测或堵转超时保护。此前日志有持续MOVE旋转指令而轮反馈接近0，负载过大、机械阻力、供电不足仍需实物排查。目标持续非零而实测接近0时，应DISARM并断开动力，不继续顶住电机。

站趴速度寄存器200→500，加速度10→20，轨迹最大行程腿每50ms约25计数（原10），规划速度约提高2.5倍，真实速度受通信、舵机响应和负载影响。80%扭矩限制与64计数跟随误差保护不变。数字键1～6的微调仍约3个百分点/秒，符合之前的慢速微调要求。

本次两板速度与电压参数都更新，需要重新烧录A/B；重启电脑网页服务并刷新。FOC记录与站趴点不主动清除，记录配置校验仍保留。先悬空低速检查方向，再落地逐步加速，观察实际轮速及温升。当前更新尚未实机验证。

### B板发热检查（2026-11-11）

先断开整机动力及B板供电并冷却，确认发热部件及供电接法后再考虑烧录或测试。本次仅修改文件并编译，不自动烧录或使能硬件。

### 操作栏、调试栏与Wi-Fi模式

标定显示修复：方向下拉框会同步最近的DIRDATA反馈，尚未应用的手动草稿不会被轮询覆盖；保存前检查四轮反馈齐全及下拉框已应用，避免把实际−1误改成默认1。连接后只有在两板轮驱动都关闭、固件支持示教时，后台自动执行一次DIRSHOW/LIMITS/TEACHSHOW只读核验。UNVERIFIED显示为“待核验：请读取舵机限位”，核验通过才显示“已核验，可用”；零偏变化、跨零点、硬件限位等异常保留对应中文提示。未自动核验时可先DISARM，再手动“读取舵机限位”。更新后重启网页服务、刷新生效，不需烧录。刷新前托住车身，按现有退出策略会请求卸力。

网页左侧“操作栏”显示日常驾驶、四腿姿态和百分比控制；“调试栏”显示FOC悬空校准、单轮按住测试、单腿±1°点动/寄存器读取、方向与站趴标定。单轮测试限±1 rad/s，同样受300ms续发失效停轮保护；单腿测试指所选舵机，不改变其他腿目标。切换栏会停止正在按住的运动。日志两栏均可查看。

连接模式可选USB串口或Wi-Fi。无线步骤：

1. 先用USB将Wi-Fi新版固件烧录到A板。B板仍通过16/17/GND的UART连接A板，不需要连接热点；若B板已是FOC缓存协议v2则本次不必更新。
2. 断开USB后，用稳定的5V逻辑电源给A/B板供电，轮/舵机仍为6V，共地；6V不能接ESP32的5V/3V3。USB与外部5V不要同时给同一板供电。
3. 电脑在系统Wi-Fi列表连接热点 **QUAD-Control**，密码 **quadrobot2026**。这是机器人本地热点，没有互联网。热点名/密码在 `src/host_console.cpp` 中可修改后重新烧录。
4. 电脑继续运行 `打开网页控制台.cmd`，默认浏览器访问 http://127.0.0.1:8765 ，选择“Wi-Fi无线”，机器人IP保持 `192.168.4.1`，点击连接。TCP端口固定9000；192.168.4.1不是网页地址。无需USB数据线，但仍需要电脑上的本机服务。
5. 连接后读取状态，确认FRONT_MASTER、两板link=1；所有使能、反馈与方向前置条件同USB模式。首次无线连接先支撑并停轮验证。

一次只有一个Wi-Fi控制连接。Wi-Fi连接存在时，A板忽略USB输入，USB仍可查看日志；切换模式前先断开。Wi-Fi控制连接建立或断开时A板关闭轮驱动、取消姿态推进，保持舵机扭矩；新连接不会恢复旧运动。主动网页断开仍执行用户要求的RELAX卸力流程。无线失联仍有主控1.5秒速度租约、2秒姿态心跳及双板500ms保护。网络输出采用非阻塞发送和有限缓冲，拥塞时可能丢日志，但不会为等待网络发送而阻塞FOC；无线实际时延和抗干扰能力需实机测试。

### 关闭网页/断开时卸力

按用户选择，点击网页“断开”，或正常关闭、刷新、离开网页时，发送STOP后发送RELAX，关闭轮驱动并请求四舵机卸力，再关闭串口。显式断开会等待最多1.2秒确认 `all_servo_torque_off_verified=1`，未收到成功确认会提示。先托住车身再关闭/刷新页面。窗口失焦、切换标签页、通信超时仍只停轮/停止姿态推进，保持舵机支撑扭矩；“关闭轮驱动”DISARM也不变。

网页退出使用keepalive请求，浏览器强制结束、电脑断电或USB断开时不能保证请求送达，也不能保证舵机卸力；需要确定卸力时，先点击“断开”或“卸舵机扭矩”并检查确认，再关网页。关闭网页服务本身仍保留原停轮/关闭轮驱动处理，不把异常退出等同于已卸力。此项只更新网页服务，无需烧录ESP32，重启服务后刷新生效。

### 轮驱动启用与可选校准

网页提供两个独立按钮：“启用轮驱动（已存校准）”发送ENABLE，读取保存的FOC方向/电角度零点，不执行对齐扫描；“重新悬空校准（可选）”发送ARM，执行四轮校准并保存新记录。两种方式都先准备两板，再以零速使能，看到state=3、peer_state=3后才可运动，上电不自动启用。

首次使用本版本仍需悬空ARM一次，原版本没有持久化FOC记录，不能从WDIR方向配置推算电角度零点。之后断电、DISARM后可直接ENABLE，无需每次重新悬空校准。FOC记录分别保存于各板NVS wheel-foc/profile；按版本、板角色、极对数、引脚、供电配置、数值范围及CRC校验，并写后读回核对。配置变更可能令记录失效。记录缺失/无效报轮故障601，存储失败602；校准开始会作废旧记录，失败后不能用旧记录绕过故障。

电机相线顺序、编码器/磁铁位置、轮电机或主控板更换后需要重新校准；软件无法自动识别机械位置是否改变。跳过的是重复扫描，不是编码器闭环和保护。ENABLE仍会使驱动输出零速保持力，不代表断电或无扭矩。首次快速启用先支撑验证。

此功能使用板间协议v2，必须同时更新A/B两板；新旧协议不会互通。重启网页服务、刷新网页。保存WDIR/站趴点位与FOC记录相互独立。若只看到“rear board link not ready”，先确认两板都烧录新版本。

网页串口常驻：页面或反馈超过3秒超时时，不再自动关闭A板串口，而是STOP、DISARM并停止姿态推进，保持舵机扭矩。恢复页面不会恢复旧运动，需要重新校准/使能轮驱动。反馈中断时暂停运动权限并定期只读查询状态，识别A板后恢复操作权限。手动“断开”、关闭服务或串口读写发生实际错误仍会关闭串口。原窗口失联超过3秒后，新窗口点击连接可接管同一串口，接管前先停轮与关闭轮驱动。无需更新ESP32，重启网页服务生效。

### 按住数字键调整姿态

| 按住的键 | 操作 |
|---|---|
| 1 / 2 | 四腿向站立点 / 趴下点移动 |
| 3 / 4 | 前腿1、2向站立点 / 趴下点移动 |
| 5 / 6 | 后腿3、4向站立点 / 趴下点移动 |

点击网页空白处使用快捷键，数字输入框中不触发。单次只控制一组腿；按新数字键切换控制组。每250ms相对最近下发目标变化0.75个百分点，约3个百分点/秒（实际受编码器计数量化、负载与限制影响），自动钳制在站趴区间内。各腿分别从自己的最近目标接续，不从百分比输入框跳转；不是按车身高度毫米匀速。松开数字键发送POSTURESTOP，取消姿态继续推进、保持最后目标，不停止轮电机驾驶；Esc/失焦则同时停止驾驶和姿态。网页350ms未续发SHIFT，本机服务也发送POSTURESTOP。

需四腿已使能、反馈正常和有效示教区间。底层SHIFT ALL/FRONT/REAR <增量比例>单次限制±0.02，网页采用±0.0075；与绝对百分比BLEND共用一条轨迹。A板重新烧录后重启网页服务并刷新，B板不需更新。首次停轮、支撑车身确认“向站立点”对应实际上升，再低速组合驾驶。

### 频繁修改百分比的修复

百分比分组：网页同一百分比输入可选“四腿一起移动”“仅前腿一起移动”“仅后腿一起移动”。前腿=1左前+2右前，后腿=3左后+4右后；未选中的两腿保持最近下发目标。串口例如 `BLEND FRONT 0.58`、`BLEND REAR 0.25`、`BLEND ALL 0.5`，原 `BLEND 0.5` 仍表示四腿。分组共用一条姿态轨迹，新组目标替换正在执行的旧轨迹；若旧轨迹包含另一组，那一组停止推进并保持最近目标，不在后台继续旧运动。当前仍要求四腿都使能、反馈正常、四套点位有效。前后组均受最新目标合并和推进限速保护。

网页连续点击BLEND/POSTURE会等待200ms并只提交最后目标，STOP/DISARM/RELAX取消尚未提交的目标。固件在自动过渡中接收新目标时保留50ms推进计时，避免重复命令将计时器清零、额外提前推进目标。新目标仍从最近下发目标接续，保留跟随误差与故障锁存保护，不自动清除已有故障。拒绝时打印状态与四舵机反馈；跟随超差打印POSTURE_FOLLOW的具体腿号、位置、目标、误差、电压和温度。

需要重新烧录A板并关闭原网页服务窗口、重新启动“打开网页控制台.cmd”、刷新网页。仅刷新网页不能更新正在运行的Python服务。若已发生servo_fault=1，先支撑、DISARM、读取S诊断；确认没有卡滞/电压温度异常后才RELAX并重新SERVOS ON。不能以反复使能来掩盖机械或供电问题。当前三行通用拒绝日志不足以反推最初故障原因，需保留首次POSTURE stopped/POSTURE_FOLLOW。

| 驱动1 EN | 右前2 MiniFOC | 右后4 MiniFOC | GPIO14 |
| 编码器供电 | 对应两个AS5600 | 对应两个AS5600 | 已核对模块的3.3V输入和GND |

每个MiniFOC的U/V/W接对应轮电机三根相线，VM/GND接6V稳压器正负。编码器和驱动必须属于同一个轮子。每路SDA/SCL只上拉到3.3V；已有合适板载上拉时不重复添加。不要把同一板的两个AS5600并到同一路SDA/SCL。

### A/B板间UART（交叉接）

| A板 | B板 |
|---|---|
| GPIO17 TX | GPIO16 RX |
| GPIO16 RX | GPIO17 TX |
| GND | GND |

这是3.3V TTL，短线连接，波特率115200（两板必须一致）。不能接6V/5V或RS232。两板串口协议带CRC、序号、启动会话和500ms超时；B板只接受A板的有效控制帧。

### A板到微雪Bus Servo Adapter(A)（同名接）

| A板/供电 | 微雪转接板 |
|---|---|
| GPIO4 UART TX | **TX** |
| GPIO34 UART RX（仅输入引脚） | **RX** |
| GND | GND |
| 稳压6V正负 | 绿色电源端子，对照正负标识 |
| 转接板跳帽 | **A位置（UART）** |

注意两种接法不同：**A↔B UART交叉接；A↔微雪Adapter(A)按厂家定义TX接TX、RX接RX。** 微雪板USB-C保持拔下。四舵机用原装3P线接微雪总线，核对G/V/S，不从ESP32的3V3或5V给舵机供电。

### 逻辑电源与USB

- 编码器用对应ESP32的3.3V；普通ESP32需要USB或稳压5V逻辑电源。**6V不接ESP32的5V/3V3。**
- 电脑调试时A板由Micro-USB供电，A板外部5V线先断开，避免外部5V与USB同时给同一板供电。B板不插USB时由5V降压板供电。所有GND共地。
- 一根Micro-USB线可先给B烧录，再给A烧录。给某块板接USB时，先断开这块板的外部5V，轮电机和舵机6V动力在烧录期间关闭。
- 6V稳压器需要承受四轮与四舵机的合计负载。首次整机测试观察6V输出压降和稳压器温升；已有母线滤波电容、保险和总开关按原电源接线保留。

## 3. 首次调试顺序

**先把车身固定支撑、四轮全部离地。校准会转动四个轮子。** 关闭动力接好所有线路，B板接5V逻辑供电，A板接电脑USB，再接通6V动力。串口/面板均只连接A板。

### 3.1 检查双板、编码器和舵机

输入`S`，应看到`role=FRONT_MASTER link=1 state=0 peer_state=0`。`state`表示本地前轮，`peer_state`表示B板后轮。

| 状态码 | 含义 |
|---|---|
| 0 | 轮驱动关闭 |
| 1 | 正在校准 |
| 2 | 本板两个轮已校准，等待另一板 |
| 3 | 已使能，可接收目标速度 |
| 4 | 本板轮控制故障 |

分别手转四轮，看wheel=1～4对应的角度变化，避免把某轮驱动和另一轮编码器配错。mag是十六进制状态，要求MD位有效、ML/MH为0；实际可能显示67，不能要求整个字节必须等于20。

输入`CHECK`，读取四舵机状态，确认1左前、2右前、3左后、4右后，电压温度合理。CHECK需要轮驱动关闭。

### 3.2 先验证四轮方向

第一次方向未标定时先保持舵机卸载、车身支撑。输入`ARM`，等待两板都校准成功并显示`state=3 peer_state=3`；任一轮极对数检查失败会使整组停机。串口会显示故障码，不要直接修改极对数。

```text
ARM
W 1 0.5
STOP
W 2 0.5
STOP
W 3 0.5
STOP
W 4 0.5
STOP
DISARM
```

每条单独回车，一次只测一个轮子。正向定义为该轮让整车前进的方向，不是从外侧看统一顺时针。`W`最多±1rad/s，1.5秒没续发W/K会自动停轮；可以用控制面板按住“单轮正转”连续观察。

如果某轮正向与车身前进相反，翻转该轮当前WDIR的符号；正确则保持当前值。首次默认值为1。必须对四个轮都显式设置一次，程序才允许F/BACK/LEFT/RIGHT/MOVE。例如（数值按实测，不是预设答案）：

```text
WDIR 1 1
WDIR 2 -1
WDIR 3 1
WDIR 4 -1
SAVEWHEELS
DIRSHOW
```

WDIR设置、SAVEWHEELS保存和LOADWHEELS恢复需要先DISARM，舵机可保持支撑。四轮都需逐行确认；成功保存显示 `WHEEL_SAVE ok=1 verified_readback=1 mask=F all_four_confirmed=1`。方向及确认状态保存在A板NVS，断电保留；之后上电可用ENABLE恢复已存FOC校准。不要把示例正负号当作实际标定结果。

### 3.3 舵机方向和当前位置中位

手动把机构放在合适的初始姿态并支撑，输入`SERVOS ON`。程序先检查反馈、卸扭矩并稳定采样，将当前位置作为**本次会话中位**，写入目标并核对后使能，不会强制转到2048。当前扭矩寄存器限制为80%，在使能时写入；须先支撑固定机构。

```text
SERVOS ON
J 1 1
J 1 -1
```

逐个测试1～4号舵机。默认方向为+1。统一定义正角度为你希望的同一种腿部动作（例如伸展方向）；反向的腿在RELAX后设置`SDIR <id> -1`，正确的腿也显式设`SDIR <id> 1`，最后SAVE。

每次J最大±5°；未完成站趴示教时，相对本次中位最多±15°；完成有效示教后，J按站趴区间限位。**本程序不跨越0/4095编码器边界**。若当前位置靠近0或4095，会拒绝一侧运动；先用原单舵机调试工程整理舵盘/机械中位，使所需行程在有效范围内，不强行绕过限位。软件窗口也不能代表实际机构不会干涉。

SDIR只是方向配置，不是自动求得的腿部几何参数。机械安装和各腿的中位需你按实物确认。每次SERVOS ON会重新捕获当前中位，RELAX后重新使能不是“自动回站姿”。

### 3.4 四个舵机的基本姿态调整

完成全部SDIR、SAVE并重新SERVOS ON后，四轮静止，输入：

```text
POSE 2 2 2 2
POSE 4 4 4 4
POSE 2 2 2 2
POSE 0 0 0 0
```

顺序固定为左前、右前、左后、右后。数值是各关节相对本次中位的**逻辑角度偏置**，不是车身高度mm或机身俯仰角。每次各关节目标变化≤5°、总范围±15°；四个目标通过同步写指令下发并逐个读回核对；机械同步程度仍受负载和响应影响。POSE保持相对中位±15°窗口及每步≤5°限制。可以使用不同偏置做小范围前后/左右姿态调整，实际效果由腿部结构和SDIR决定。

### 3.5 四轮基本运动

先SERVOS ON保持合适姿态，再ENABLE（首次需悬空ARM）等待两板状态3，确认四个WDIR都已保存，之后从0.5rad/s开始。

```text
F 0.5
STOP
BACK 0.5
STOP
LEFT 0.5
STOP
RIGHT 0.5
STOP
```

这些命令只保留1.5秒运动租约，期间输入K或重新发送运动命令才会继续。**推荐使用电脑控制面板，按住方向按钮运动、松开停轮；窗口失去焦点也停止续发。** 初次落地前先支撑车身验证实际方向和电源余量。

`MOVE <forward> <turn>`按左轮=forward−turn、右轮=forward+turn混合。参数均是轮角速度分量rad/s，不是m/s或机身角速度；单轮目标最大±7rad/s，转向分量最大±1.5rad/s。左右同速前进，左右反向原地转向。整车运动要求四舵机已使能且反馈正常；单轮W可在舵机未使能时做悬空测试。

### 启动与连接

2. 双击工程内 `打开网页控制台.cmd`；或在VS Code的PowerShell终端依次运行下面两行，启动服务并自动用Windows默认浏览器打开网页：

& "..\.tools\Scripts\python.exe" tools/web_panel.py
```

3. 浏览器打开 http://127.0.0.1:8765 ，选择A板端口，点击“连接A板”。首次连接不自动使能。

**服务已经启动，只想重新打开网页**：在另一个PowerShell终端运行下面这一行，使用系统默认浏览器打开，不重复启动服务：

```

如果自动打开浏览器没有生效，也可以运行上述命令。仅打开网址不会启动后台服务；页面无法访问时先运行第2步。服务运行中的终端会持续占用，这是正常现象；按Ctrl+C会关闭服务并断开串口。更新服务代码时先停轮、断开网页连接，再Ctrl+C退出并重新启动，最后在浏览器按Ctrl+F5刷新。出现“地址已被占用”时，说明8765端口已有服务运行，不要重复启动。

### 驾驶与关节同时控制

- 行驶和旋转速度分别设置，初始均0.5 rad/s；鼠标按住方向按钮运动，松开停轮。
- 键盘W前进、S后退、A原地左旋、D原地右旋；输入框或按钮聚焦时不触发驾驶快捷键，先点击页面空白处。
- 原地旋转时同侧前后轮同向、左右两侧反向；弧线转向自动等比例限幅。
- 舵机已使能且无故障后，可按住键盘行驶，同时用鼠标点动关节±1°；J/POSE允许与行驶组合。自动姿态过渡中不接受J/POSE，轮校准期间不接受姿态操作。
- Esc或“停轮”发送STOP：轮速归零并取消姿态目标继续推进，舵机保持最后下发目标；需要卸扭矩时先支撑再RELAX。

### 四腿统一百分比

前提：四腿已完成有效站立/趴下示教，舵机已使能且当前位置在标定区间。百分比不是扭矩百分比或车身高度毫米。

- 0%＝各腿趴下点，100%＝各腿站立点；50%＝各腿编码器区间中点。
- 滑条或数字框选择0～100%，点击“四腿一起移动”；调整输入本身不发运动指令。也可点击25%/50%/75%快捷按钮。
- 串口等效命令：`BLEND 0.75` 表示75%；`POSTURE STAND` / `POSTURE LIE` 分别为100% / 0%。
- 四腿按各自区间插值、共同进度推进，每50ms最大行程腿约推进10计数（原5计数），约为原规划速率的2倍。同步广播下发目标后逐个读取目标寄存器核对。提高的是速度参数及规划上限，不保证负载下实测速度翻倍。
- 支持百分比/站趴与驾驶组合；首次先停轮、支撑车身验证，再低速组合。无法跟随目标超过64计数（约5.6°）时停止推进，保留最后目标，不自动卸扭矩。

### 标定、保存和回中

先DISARM，在“方向与站趴标定”中逐轮应用方向并保存。读取舵机限位后，支撑固定、手动摆出合适站姿或趴姿，勾选固定确认，再记录；记录会卸扭矩，不要用机械硬顶点作为示教点。两组点位齐全后TEACHSAVE保存。

原位回中SETMID会修改舵机零偏，并清除该腿旧示教点；固定机械中位后执行，再重新示教。它不是让带连杆的舵机旋转到2048。跨0/4095、零位改变或点位无效时拒绝百分比运动。

### 连接与停轮保护

日志默认关闭“自动滚动”，新日志到来时保留当前滚动位置。勾选“暂停日志显示”可冻结日志文字以阅读/复制，后台仍接收数据并执行保护；取消后显示当前保留的最近300行。“查看最新”解除暂停并跳到当前日志底部；需要持续跟踪最新输出时勾选“自动滚动”。本次仅更新网页文件，不需烧录。刷新前请托住车身：按现有设置，刷新/退出页面会请求舵机卸力。

- 网页每100ms续发驾驶；本机服务300ms未收到驾驶续发发送STOP。失焦、松手会停止续发。
- 网页或设备超过3秒无反馈，本机服务尝试STOP、DISARM。服务异常退出时依靠主控1.5秒运动租约停轮；双板500ms通信保护独立保留。
- HOST_ALIVE心跳独立于REPORT ON/OFF，防止关闭周期日志被误判断线；心跳不会延长轮速度租约。
- 停轮不等于断开舵机扭矩。RELAX可能使车身失去支撑，使用前先固定车身。

## 6. 保护与实际边界

- 上电轮驱动关闭，不自动校准或运动。驱动EN应有合适硬件下拉，防止复位时悬空；软件上电后拉低不能替代复位阶段的硬件默认状态。
- 每块板FOC任务独占两路编码器，core1周期运行；core0处理控制台、舵机和双板通信。loop_hz是实际运行统计，双轮负载仍需上板验证。
- 轮控制请求/双板通信超过500ms未更新，禁用轮驱动；主控轮运动租约超过1.5秒，四轮目标归零。
- 对端重启或轮控制故障需要重新ARM，不能靠旧RUN帧自动恢复。协议CRC、序号和启动会话减少串线噪声/旧帧误用，不是网络认证协议。
- 校准每板两轮依次进行，两板可并行。SimpleFOC校准内部会阻塞数秒，期间软件STOP/通信超时不能保证立即中断正在执行的对齐，应保持四轮悬空，异常时使用物理动力开关。
- 极对数检查失败、磁场状态连续异常、超速或控制任务间隔异常会停轮。无电流采样，不是电流闭环，不提供实测堵转电流保护。
- 舵机反馈/电压/温度异常会停轮并保留现有舵机目标。通信失联后不能保证舵机实际扭矩状态；车身须有物理支撑/急停方案。
- RELAX会释放支撑力。软件不自动断舵机扭矩超时，防止通信短暂中断导致车身下落；测试结束主动支撑、RELAX、断动力电。
- 方向通过SAVEWHEELS/SAVE保存，舵机点位通过TEACHSAVE保存；SETMID/RESTOREMID会显式修改舵机零偏。不使用IMU闭环或自动平衡，也没有几何步态规划。

### 轮故障码

码中的+1表示本板第二个轮（A板轮2或B板轮4）。

| 码 | 含义 |
|---|---|
| 101/102 | 校准前磁铁/编码器状态异常 |
| 201/202 | PWM驱动初始化失败 |
| 211/212 | 电机对象初始化失败 |

## 7. 烧录失败排查

先关闭网页串口连接与串口监视器。支撑车身、关闭6V动力，烧录板只保留USB供电。当前烧录速率115200，端口以实时枚举为准，不能在COM与数字之间加空格。无需运行Activate.ps1。

| 提示 | 处理 |
|---|---|
| UnknownEnvNamesError | 在本工程目录运行，环境名为front_master或rear_follower |
| Could not open COM / port doesn't exist | 检查实际COM号，确认不是COM 12；拔插后重新列举 |
| No serial data received / Wrong boot mode | 确认端口，手动BOOT+EN进入下载模式 |
| Packet content transfer stopped | 检查USB线、接口、供电，避免扩展坞；当前已降速115200 |
| Invalid head of packet | 已有串口回复但数据包损坏；先做板子仅接USB的对照测试，不据此判断应用代码错误 |

手动下载步骤：按住BOOT→启动上传→出现Connecting时短按EN/RST（BOOT仍按住）→出现Chip is ESP32或Writing后松开BOOT。若仍失败，断电拍照记录接线，暂时拔除烧录板外接线，仅留USB，换已验证的数据线并直连电脑接口再试。只接USB仍失败时，用同一线和接口对照测试另一板。

## 8. 运行错误定位

轮校准详细诊断：每轮输出 `WHEEL_CAL_BEGIN wheel=...`，失败输出 `WHEEL_CAL_FAIL`，成功输出 `WHEEL_CAL_OK`，并启用SimpleFOC的MOT日志。`front=302`指2号右前轮，`rear=302`指4号右后轮；302合并FOC初始化、极对数检查与校准后编码器检查，单凭此码不能判断具体机械/电气原因。reason字段包括init_foc_failed、pole_pair_check_failed、encoder_postcheck_failed，结合init_foc、pp_ok、mag、encoder_ok、direction及MOT估算极对数判断。出现时保存从该轮BEGIN到FAIL的完整日志；B板细节需要读取B板USB，A板只收到后板故障码。

- `rear board link not ready`：未建立有效后板通信；检查B板逻辑供电、两板16/17交叉接及GND。GND口用完可通过可靠接线端子或绝缘焊接做分支，不能省去共地。
- 后轮`valid=0`表示后板通信数据不新鲜/握手无效，不直接等于编码器损坏。旧角度可能仍显示。
- `board link timeout/not handshaken`：有效后板帧超过500ms未更新；保留同一次的LINK_REJECT、LINK_TIMING、LINK_DIAG，不通过调大超时掩盖问题。windows为被拒绝的滑动窗口数，不等于丢包数；max_loop_gap_ms是启动以来的历史最大间隔，不一定属于本次故障。
- `rear=302`：B板第二轮，即4号右后轮FOC校准检查失败；结合校准日志检查磁铁、相线、供电和是否悬空。
- `WDIR requires wheels OFF`：先DISARM，再应用方向并保存，不必释放舵机支撑扭矩。
- `SERVOS ON with valid feedback required`：读取S确认servos_active、servo_fault与四舵机反馈，先排除故障再恢复使能。
- `servo cannot follow target`：实际位置与目标差超过64计数。支撑、DISARM、读取S，对比pos与goal_cache，并检查负载、卡滞、电压及温度。不要反复顶住机构。
- `尚未确认A板固件`：读取S或重新连接确认FRONT_MASTER，确认网页服务与A板均已更新心跳版本。

### 配置核验与站趴点位的区别（修复待核验提示）

“重新核验舵机配置”对应LIMITS，只读取舵机内部角度上下限、零偏、相位和反馈；不会寻找机械止挡，不会改变站趴点位。站立/趴下点记录才定义实际软件活动区间。

配置核验会有限重试，失败显示CONFIG_READ_FAILED而不再只显示UNVERIFIED；日志SERVO_CONFIG_FAIL提供腿号与失败项掩码。反馈读取连续失败显示SERVO_FEEDBACK_FAIL。读取配置不会因一次反馈失败而被直接跳过，也不会将未核验强行标为有效。已有站趴点和有效安全边界均保留。

SERVOS ON重复点击时，健康的已使能状态只提示已就绪，不再输出通用失败；若故障锁存则明确显示fault，先读取S和具体错误再处理。新诊断需更新A板，重启网页服务并刷新；无需重录原站趴点，但核验若提示零偏变化/跨零点仍须按实际情况处理。
