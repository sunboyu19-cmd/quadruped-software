# 08 普通ESP32：轮电机逐一FOC测试

独立工程`08_ESP32_WheelDiagnostic`，环境`wheel_diagnostic`。使用现有普通ESP32-WROOM、PCA9548A/TCA9548A和四块MiniFOC/DRV8316，无需改05接线。每次只对所选轮子校准、发送速度目标；不使用IMU、不启动WiFi/蓝牙、不初始化舵机串口、不写NVS。上电共用EN26低，默认选择1号且不输出PWM、不自动校准、不自动转动，周期日志默认关闭。

**运行电压限幅仍为2.5V**，6V母线、7极对、校准1.5V、25kHz PWM。程序不能把输入电源自动变成6V，供电仍需实际6V稳压器。无相电流或温度采样，不能用软件限幅代替供电、发热检查。

## 当前接线

| 编号 | 位置 | 编码器通道 | PWM A/B/C |
|---:|---|---:|---|
| 1 | 左前 FL | 7 | GPIO4 / 16 / 17 |
| 2 | 右前 FR | 2 | GPIO13 / 14 / 27 |
| 3 | 左后 RL | 6 | GPIO21 / 22 / 23 |
| 4 | 右后 RR | 1 | GPIO5 / 18 / 19 |

GPIO25→多路器SDA，GPIO33→SCL；多路器地址0x70、各AS5600为0x36。编码器和多路器3.3V供电、全部共地。IMU通道0不被读取或选通；其余编码器故障不作为所选轮的启动前提，`CHECK`才显式检查四路。若公共上游总线仍被异常支路拉死，所选轮也无法通过预检。

四个MiniFOC的EN均接GPIO26，并应按05接线要求有可靠下拉。**共用EN意味着所选轮校准或运行时，其他三块驱动的功率级也使能，但其PWM全部为零，可能对其他轮产生电气制动；不等于硬件独立断电。** 因此四轮全部离地，车身用固定支撑托住；不要用手阻挡测试轮。四个PWM驱动只在全组EN低时一次初始化，切轮不重复分配PWM资源。

6V只供MiniFOC动力和原有舵机侧，不能接ESP32的5V/3V3。08不改变舵机扭矩状态，不能依赖舵机一定保持或一定卸力来支撑车身。开始前确认6V正负、相线和编码器通道正确，物理电源开关能随时切断动力。

## 第一次测试1号轮

先保持动力关闭，输入以下命令，仅验证编码器，手动转动对应转子观察角度：

```text
H
I 1
CHECK
S
```

确认所选轮`magnet_ok=1`、CHECK的`status_read=1 angle_read=1`，并核对角度只随对应轮变化。`CHECK`不输出动力。默认I²C为100kHz，便于先排查焊线；主工程05使用400kHz，需要在本工程停止状态下用`SPEED 400000`重新检查、重新校准后验证。

**接下来CAL和RUN会使电机通电运动。** 先固定车身、四轮悬空，再接通正确6V动力。先输入CAL，等完成再继续，不要把所有命令一次粘贴：

```text
CAL
```

等到`CAL_OK ... outputs OFF`说明所选轮FOC对齐成功，输出随后关闭；这一步电机会扫动以确定方向和电角度，7极对检查必须通过。没有成功提示就不要运行。

然后输入：

```text
REPORT ON
RUN 0.5 3
```

所选轮以0.5rad/s目标运行3秒，到期显示`RUN_DONE ... outputs OFF`并关闭共用EN。观察`foc_w`是否接近目标、是否明显抖动或顶住不动。运行中的正负号只表示FOC机械方向，不自动套用05的WDIR车身前进方向。

再测反向：

```text
RUN -0.5 3
```

随时输入`D`或`STOP`关闭EN；`REPORT OFF`只停止日志，不是停轮。切到其他轮按下面做，并在各自CAL成功后再RUN：

```text
D
I 2
CAL
```

等CAL_OK后运行`RUN 0.5 3`；3号和4号同理。不同轮子的校准在本次上电期间分别保留，已校准轮可再次选择后直接RUN。断电丢失；改变I²C速率会使本工程校准失效。08既不读取也不覆盖05的校准记录，回05后需用05自己的有效记录或重新校准。

## 串口命令完整表

| 命令 | 功能 |
|---|---|
| `H` | 帮助 |
| `I 1` / `I 2` / `I 3` / `I 4` | 停止状态下选择左前/右前/左后/右后，不自动转动 |
| `CHECK` | 停止状态下检查四个编码器，跳过IMU |
| `S` | 一次所选轮状态，含磁场、角度、速度、输出和错误 |
| `CAL` 或 `A` | 只校准所选轮，完成后关闭输出，四轮须悬空 |
| `RUN 0.5 3` | 所选轮目标0.5rad/s，运行3秒后关闭输出 |
| `RUN -0.5 3` | 反向测试 |
| `V0.5` / `V-0.5` | RUN的简写，默认3秒 |
| `D` / `STOP` / `DISARM` / `V0` | 关闭全组EN，不保持零速扭矩 |
| `REPORT ON` / `REPORT OFF` | 每500ms打印/停止打印所选轮状态；默认OFF |
| `SPEED 100000` / `SPEED 400000` | 停止时切换I²C频率，清除本次上电的全部轮校准 |

RUN速度范围为非零±12rad/s，单次时间0.1～10秒；建议从±0.5rad/s开始。本测试不自动续发或无限运行；运行中再次发RUN是明确更新目标/结束时间。`RUN 0 ...`等同停止。任意故障后不会靠旧RUN请求自动重启，需D清状态、排查后再校准/测试。

## 输出与保护

- `en`为共用EN状态，`mode=off/calibrating/run`为任务状态，`calibrated=1`表示本次上电所选轮已对齐。
- `a`、`encoder_w`为编码器角度/速度（rad、rad/s），`foc_w`是运行时FOC采用的机械速度，`target`目标rad/s，`uq`为命令电压，不是电流。不同方向映射下原始编码器速度符号可能与FOC速度不同。
- `magnet_ok=0`：状态读失败、无磁铁或磁场过弱/过强；`CHECK status_read=0`更偏向I²C通信问题，`status_read=1`但magnet_ok=0则检查磁铁标志。
- 故障101～104：所选轮编码器/磁场预检；111～114：角度初始化；201：PWM初始化失败，须重启后排查；211～214：电机初始化；301～304：所选轮FOC或极对检查失败。
- 401：主命令任务刷新超时500ms；402：校准或启动取消；403：控制循环/I²C耗时异常；405：速度非法/超速；501～504：磁场/通信连续异常；511～514：角度连续读失败；520：目标≥0.5rad/s、实际速度<0.1rad/s且输出接近限幅持续约2秒，疑似堵转；601：RUN前校准/磁场/目标/结束时间条件未满足。
- 堵转判定是诊断性条件，不是电流或温度保护，不能替代人工观察。轮子受阻、抖动或发热时D并断开动力，不持续提高电压硬顶。
- Core0解析命令，Core1独占I²C/PWM。D/STOP先发布取消再直接把共用EN拉低；允许拉高EN的代码会在同一锁内核对最新命令代次，防止旧校准在STOP后重新使能。SimpleFOC对齐仍有阻塞段，控制任务需等其返回才更新完整状态；物理切断动力仍是紧急停机手段。

本工程交付时进行编译和参数/计时边界的编译期检查；尚未代为烧录或实际驱动轮电机。不能把编译成功当作电机、供电或机械机构已验收。
